# agent-connector V1.6 迭代记录

## 变化内容

1. 发给其他会话 `/to`（2026-11-16）。用户原话（飞书）：“agent-connector新增一个功能，支持同channel agent下跨会话发送消息：通过发送指令，指定会话，后面加上正文，agent就会向该会话发送消息，然后对方会话会通过thread回复该消息，后续在thread里的消息都是发生在该会话下；该channel agent不修改会话；指令形式：/{指令名} {会话名} {正文}”，并要求先看可实现性、定义是改接口还是渠道内部能力。
   - 先做了可实现性测试（真实飞书，Cora）：机器人能“在话题中回复”（`lark-cli im +messages-reply --reply-in-thread`）；话题里的消息带 `thread_id` 和 `root_id`（`root_id` 是话题所挂的消息），事件定义里也有这两个字段；回复话题里的消息会自动留在话题里。Agent 侧就是续接指定会话，Claude Code 和 Codex 已具备。
   - 定义：扩展渠道接口（消息的可选字段 `thread`、回复条目的可选项 `inThread`、渠道声明 `threads`），中枢负责“话题 → 会话”；Agent 接口不变。
   - 用户确定（飞书）：“指令名用/to；和/switch一样；群聊不行；话题沿用所在聊天的设置；冲突处理沿用现有规则”。
   - 实现：话题在中枢里是一个单独的聊天（键为“聊天#话题根消息 ID”），有自己的会话记录、队列和 `/stop`，权限模式、模型、推理深度读写所在聊天的。`/to` 在收到时就检查（只读文件），通过后把正文作为话题的第一条消息排进话题的队列，所以不占主聊天的队列。话题里拒绝 `/new`、`/temp`、`/keep`、`/dir`、`/switch`、`/to`、`/test`。飞书：`normalize` 只在有 `thread_id` 时带 `thread`（引用回复也有 `root_id`，不算话题），文字、卡片、文件三种回复都支持 `inThread`。接入测试新增渠道项 `thread`（自动）和 `thread-receive`（需要用户在话题里回一句）。

   以下取舍由 Agent 自行决定，未经用户确认：会话名里有空格时按能匹配上的最长会话名切分；话题里改 `/mode` 等改的是整个聊天的设置（由“沿用所在聊天的设置”推出）；话题里拒绝的指令范围；话题记录不会自动清理。
