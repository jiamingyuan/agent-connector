## 变化内容

1. 切回默认会话也发前情梗概：原先从列表选中这个聊天自己的默认会话等同 `/exit`，只回一句话。现在同样生成前情梗概，回复“已退出会话「…」，回到默认会话「…」”加目录、最近活动和梗概；`/exit` 仍只回一句话。验证：集成测试 67 项通过；未在真实飞书中验证。**已被第 2 项取代**：不再有默认会话。

2. 会话不分主次：每个聊天只记一个当前会话（`state.sessions`），原先单独保存的“`/switch` 进入的会话”（`state.attached`）在启动时并入并删除。`/new` 清空当前会话，下一条消息在 `sessionDir` 新建，回复“已离开会话「…」，它仍在 /sessions 列表中”；`/switch` 切到任一会话（包括机器人开的）都发前情梗概；`/exit` 取消，发送时提示改用 `/switch` 或 `/new`；`/switch 0` 取消。所有会话一视同仁：每轮都带“消息来自飞书”的说明，不在 `workspace/` 中运行时都带 `workspace/CLAUDE.md`，会话目录或记录丢失、终端正在执行时都会拦下；没有名字的会话在第一次回答后自动起名；`/rename` 回复统一。README、接口说明和列表底部提示同步修改。验证：集成测试 67 项通过（包括旧格式状态的迁移）；未在真实飞书中验证。

3. 飞书卡片回复（`replyFormat: card`）：标题区为会话名与三个标签（权限模式、模型全称与推理深度、context），正文上方是 5 小时与本周额度（剩余比例与 UTC 重置时间，用色块表示进度），回答的最后一张卡片底部是本轮用时、输出、新增输入、缓存读取。数据由 Claude Code 适配器从每轮事件读取（`onStats`）：模型与 context 取主线最后一次调用的 usage，额度取 `rate_limit_event`，本轮 token 取 `result.usage`；中枢按会话记下模型与 context、按账号记下额度，`/compact` 后更新 context，`/switch` 后从会话记录读取。飞书拒收卡片时改发富文本。新配置 `claudeEffort` 以 `--effort` 传入并显示。验证：单元与集成测试 70 项通过；真实 Claude Code 2.1.319 实测：Opus 与 Sonnet 5.5 的 `contextWindow` 都是 1M（预览早期写的 200k 是 Agent 随手填的错误值），`result.usage` 为本轮值而 `modelUsage` 在续接会话时是累计值，auto 模式的安全检查调用（haiku）不计入 `result.usage`；向本聊天真实发出一张示例卡片，飞书接受；改用卡片后的真实回复待用户确认效果。上线后用户反馈色块进度条在手机上显示异常，问是飞书局限还是 bug（属于 Agent 的实现方式：卡片没有进度条组件，字符宽度随字体变化），随后决定“就不要进度条了，这样也能展示utc”（飞书）：额度改为纯文字，剩余比例按颜色区分。

4. 撤回消息即中断（2026-11-10）：用户撤回一条消息后，中枢取消它正在运行的那一轮、跳过还在排队的它、丢弃没发出的回复，也不再回复；同一聊天的其他消息照常，已做的操作不撤销。渠道接口新增两种接法（`core/README.md`“撤回的消息”）：有撤回事件的平台调用 `handlers.recalled(id)`；没有的提供 `isRecalled(message)`，中枢在消息处理期间每 `recallCheckMs`（默认 5 秒）问一次。飞书走后一种：`lark-cli` 1.0.99 的事件列表里没有撤回事件，改查消息的 `deleted` 标记（用 `--jq` 只取这一项，不读正文），每次约 1.2 秒。验证：新增 4 项测试，全部 74 项通过；查询方式用两条以前被撤回过的真实消息和一条正常消息核对过；未在真实飞书中撤回消息验证。开销实测：每次查询约 0.13 秒 CPU、48 MB 内存峰值，空闲时不查（用户：“没事，就这样好了”）。
