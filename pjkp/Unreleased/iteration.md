# Unreleased

V1.4 之后、尚未命名版本的工作。

## 变化内容

1. `/delete` 可一次删除多个会话（2026-11-12）。用户原话：“将/delete做成能够批量删除会话的能力”（飞书）。
   - 写法：多个编号和范围，如 `/delete 1 3 5-7`，分隔符可用空格、逗号、顿号。写名称或会话 ID 时仍按单个会话处理。
   - 不能删的（当前会话、终端里开着的、正在执行任务的、别的机器人开着的、列表里没有的编号）列出原因并跳过，其余照常删除。
   - 确认：发同一条命令加“确认”。只有本次要删的会话和上一次列出的完全一致才删除，否则重新列出。
   - 实现在中枢 `core/hub.mjs` 的 `deleteSession`，Agent 接口 `trash` 不变，每个会话调用一次。

   以下取舍由 Agent 自行决定，未经用户确认：支持范围写法；一个范围最多 100 个编号；没有做“删除全部”。

2. Windows 适配（2026-11-12）。用户先问“现在agent-connector是否兼容mac、windows”，得知 Windows 只能经 WSL 后要求“帮我做一下windows的适配”（飞书）。此前 `service.mjs` 和 `doctor` 在 Windows 上直接报错退出。
   - 启动和结束外部程序统一到新模块 `core/process.mjs`，Agent 和飞书渠道都改用它。原因：Windows 上 npm 装的工具是 `.cmd` 启动脚本，Node.js 只能经 `cmd.exe` 运行它，而消息内容是作为参数传给 `lark-cli` 的，经过 `cmd.exe` 会被当成命令解释。所以改为找出 `.cmd` 实际运行的脚本或程序直接启动；找不出就报错，不退回到 shell。
   - Windows 没有进程组和 SIGTERM：结束任务用 `taskkill` 结束整个进程树。
   - 服务：Windows 用内置守护进程，`install` 在当前用户的注册表启动项登记，登录后启动。守护进程改为经通道请求桥接程序关闭、经请求文件（`runtime/supervisor.stop`）接收停止请求，这两点在所有系统上相同，因此在 Linux 上测得到。守护进程启动桥接程序前清掉失效的锁文件（Windows 注销或断电不会清锁，锁里的进程号可能已被别的程序占用）。
   - 其他：下载结果的路径比对在 Windows 上不分大小写并兼容短路径名；保存的文件名避开 Windows 的设备名和结尾的点；状态文件改名失败时在 Windows 上重试。
   - `.github/workflows/test.yml`：让 GitHub 在 Linux、macOS、Windows 上各跑一遍测试。

   以下取舍由 Agent 自行决定，未经用户确认：登录自启用注册表启动项而不是计划任务或系统服务（不需要管理员权限，代价是登录后才启动、登录时短暂出现命令行窗口）；加了测试工作流。

3. 补全 Codex 模块（2026-11-12）。用户原话：“在agent-connector迭代了这么多版之后，看看codex模块是否开发完全，没开发完全的你先补上，不用进行测试”（飞书）。此前 Codex 只有文字对话、`/model`、`/effort`，且固定在 `workspace` 里运行。
   - 补上：按会话目录运行、图片、收发文件的目录放开、`/mode`（沙箱模式）、`/usage`、`/rename`、`/sessions`、`/switch`、`/delete`、回复卡片上的模型 / 上下文 / 额度 / 本轮 token、失败原因。各项的做法和与 Claude Code 的差别见 README 的 Codex 一节。
   - 依据：Codex 0.167.2 的官方源码（`codex exec` 的参数与事件、会话记录和名称索引的格式）。本机没有装 Codex，下载的程序被权限规则拦住没有运行，所以只读了源码。
   - 没有做 `/compact`：`codex exec` 没有对应命令。
   - 为此改了中枢两处，对 Claude Code 没有影响：Agent 可以给出说明文件名（`instructionsName`）和新会话的默认目录（`sessionDir`）。会话列表的公共部分移到 `core/session-list.mjs`。

   以下取舍由 Agent 自行决定，未经用户确认：新会话默认仍在 `workspace` 里（会话目录就是沙箱可写范围，放到主目录会放大写入范围）；`/rename` 的名称存在桥接程序自己的文件里，不写 Codex 的名称索引（那个文件要求加文件锁，Node.js 做不到）；`/usage` 取最近一次回答时的数据。

4. 接入测试 `/test`（2026-11-12）。用户原话（飞书）：“起一个新的版本，需要开发一个接入测试：对于 agent-connector 已有的每个功能，测试可用性；agent侧测试agent是否可用所有能力；channel侧同时测试channel是否可用所有能力；在一个agent首次部署agent-connector时，询问用户是否进行当前agent的测试；该测试由于区分不同的agent和不同的channel，我理解是要每个模块都进行开发；lark如果每接入一个新的飞书agent，也可以咨询一下用户是否做测试；也需要有方法手动调起测试，这里的交互方式你来定义”。
   - 做法：通用测试项放在中枢（`core/selftest.mjs`），按接口功能生成，模块提供了哪项就测哪项；模块再用 `selfTest` 声明只有自己知道怎么查的项（Claude Code：会话能否出现在终端 `/resume`；Codex：会话记录能否读出；飞书：按 ID 读消息、大文件经云空间）。这样新模块实现了接口就自动有测试，同时每个模块都有自己的测试入口。
   - 交互（用户让 Agent 定）：聊天里 `/test` 列出测试项，`/test all | agent | channel | 项目名` 运行；只能在私聊。Agent 部分在单独的测试会话里跑，结束后删除；渠道部分里接收图片、接收文件、撤回三项要用户按提示发消息，可回复“跳过”。测试期间这个聊天的其他消息留到测试结束后处理，`/stop` 可停止。
   - 首次接入的询问：按 Agent 和机器人各记一次（`runtime/state.json` 的 `selftest`），在它接入后的第一条私聊消息时多回一条询问，只问一次；`offerSelfTest: false` 可关。
   - 为了能测出失败，渠道的 `send` 和 `acknowledge` 加了 `strict` 选项：平时照旧吞掉错误或降级，测试时直接报错。

   以下取舍由 Agent 自行决定，未经用户确认：没有做命令行入口，只有聊天里的 `/test`（渠道测试需要一条真实消息来回复）；高风险的权限模式不测；会留下东西或代价高的项（飞书 `drive`）不进 `all`，只在点名时运行；升级后已有的 Agent 和机器人也会各被问一次；富文本和卡片只确认发送成功，显示效果靠用户自己看。

5. 项目规则与“功能与模块”表（2026-11-12）。用户原话（飞书）：“做一个项目级的规则吧，每次新增一个功能，同时开发所有存量模块，并测试；在readme里加个功能模块（已有则改造）通过表格形式展示功能和模块测试情况，测试过了就写已完成，开发完就写已开发，未开发的就写未开发；先把当前运行的agent和channel都完成开发和测试”。
   - 规则写进 [rules.md](../rules.md) 第 1 条。README 新增“功能与模块”一节，Agent 一张表（Claude Code、Codex）、渠道一张表（飞书），每格是已完成、已开发或未开发，并标出对应的 `/test` 项目名。
   - 为了让“超时停止”也能测，接入测试加了 `timeout` 一项。
   - 当前在用的 Claude Code 和飞书已在真实环境测过，结果见下面“验证”。

   以下取舍由 Agent 自行决定，未经用户确认：模板 `example-agent/` 不列入表；没有 `/test` 测试项的功能，凭服务日志里的真实使用记录判定“已完成”，表里注明了依据。

6. 临时会话 `/temp`、`/keep`（2026-11-12）。用户原话（飞书）：“增加一个temp会话能力，channel通过指令打开一个temp会话，等到会话被切换掉之后自动删除会话，同时再加一个持久化指令，如果用户觉得temp会话值得持久化，则输入这个指令，这个会话就会变成一个常规会话”。
   - `/temp` 开临时会话，用法同 `/new`；聊天离开它时（`/new`、`/temp`、`/switch`）中枢调用 Agent 已有的 `sessions.trash` 把记录移到回收目录。`/keep` 去掉临时标记并自动起名。临时标记记在聊天的会话记录上（`state.sessions[chat].temp`）。
   - 按规则 1 覆盖所有模块：功能建在已有接口上，Claude Code 和 Codex 都不需要改动就可用；渠道只是多两条文字指令，飞书不需要改动。

   以下取舍由 Agent 自行决定，未经用户确认：指令名用 `/temp` 和 `/keep`；删除是移到回收目录而不是彻底删除；临时会话没有时限；还有别的聊天在用、终端里开着或 Agent 不支持删除时不删并说明；临时会话不自动起名，保留时才起名。
