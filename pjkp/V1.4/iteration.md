## 目标与范围

- 用户：“在agent侧能够配置不同channel agent能访问会话的范围、mode的范围、模型的范围，并且有办法选择全部（比如'all'）”。

下文把“channel agent”称为机器人：某个渠道上的一个机器人身份，例如飞书应用 Sophia。

## 变化内容

1. 多个机器人：`config.json` 新增 `bots`，每项是一个机器人（名字、渠道、渠道配置、访问范围），没写的设置沿用顶层；没有 `bots` 的旧配置照常是一个机器人。入口为每个机器人建一个渠道实例，中枢按机器人区分聊天、消息、待发回复和连接状态，回复交回收到消息的那个实例；同一条平台消息被两个机器人收到时各处理一次。从旧配置改成 `bots` 时，原有聊天状态归第一个机器人。`doctor`、启动前检查、`status.json`、`/status` 同步支持。
2. 一个会话同一时间只属于一个机器人：别的机器人 `/switch` 或 `/delete` 时拒绝，并提示“正由机器人 X 开着”；那边 `/new` 或 `/switch` 离开即释放。
3. 访问范围 `access`（中枢统一执行，渠道和 Agent 接口不变）：`sessions` 为 `all`、`own`（只限自己开的）或目录列表；`modes`、`models` 为 `all` 或名单。会话列表、切换、删除、继续对话、新会话目录、`/mode`、`/model` 都按范围过滤或拒绝；名单里有 Agent 不认识的名字时启动报错。

4. 按会话排队：同一个会话上的任务（对话、压缩、改名）一次只跑一个，另一个聊天的消息等前一个结束再执行，等待中被 `/stop` 或撤回则不再执行。此前这种消息会被拒绝并提示“正在终端里执行任务”：桥接自己启动的 Claude Code 进程也会登记为忙（2026-11-11 用真实 Claude Code 2.1.322 核对），现在不再把自己的任务当成终端任务。

验证：新增 5 项测试（其中一项用两个假的飞书应用跑完整流程），全部 82 项通过。`lark-cli` 1.0.99 两个应用同时监听已实测（用户：“lark-cli支持度，你测试一下”）：每个应用有自己的事件守护进程，发给 Cora 的消息只到 Cora 的监听，Sophia 的监听不受影响；同一个人在两个应用里的 open ID 不同。

## 决定

- 不做真正的隔离（用户：“不做真正的隔离”）。
- 不需要跨机器人认出同一个人（用户：“不同的飞书agent目前暂时不需要能够分清同一个人”）；授权用户按机器人分别配置。
- 会话独占保留，`/new` 或 `/switch` 离开即释放，不加闲置自动释放（用户：“独占不用管，不需要退出机制”；Agent 复述这一理解后，用户：“你的理解正确”）。
- 不限制同时运行的任务数（用户：“同时运行任务数不用配置”）。
- 第二个应用用用户已有的 Cora（用户：“用我已有的应用Cora”）。
- 独占只在不同机器人之间生效；同一机器人的不同聊天可以进入同一会话，也不提供把聊天绑定到指定会话的配置（用户：“那还是一个机器人不固定一个会话吧，但同时也不限制不能一个对话”）。按会话排队（变化内容第 4 项）是 Agent 对用户“开始开发吧”的理解，未经用户确认。
- 由 Agent 决定，未经用户确认：会话范围用“`all`、`own`、目录列表”表达（解释后用户未反对）；默认权限模式或模型不在名单里时取名单第一项；限定目录的机器人新会话开在范围内的 `sessionDir`，否则开在第一个目录；`own` 只认 V1.4 起记录的“谁开的”，此前的会话不算任何机器人自己的；推理深度不设范围。

## 候选与调研（都未决定，不是待办）

- 不经 `lark-cli` 连接飞书（用户：“帮我调研agent-connector连接飞书的方式一定要通过lark-cli吗”，2026-11-11 只读调研）：不是必须。可用官方 SDK 的长连接（Node 版 `@larksuiteoapi/node-sdk` 1.76.0，只需能访问公网）、Webhook 回调（需要公网地址和验签），或 SDK 自带的 Channel 模块。换 SDK 能得到撤回事件（包里有 `im.message.recalled_v1`；官方文档该事件的推送方式只写了 Webhook，能否走长连接未实测）、省掉每次约 1.2 秒的进程启动、更多事件；代价是 App Secret 要由本项目自己读取、新增依赖（解压约 29 MB）、收发与 Markdown 转富文本要重写。Agent 的建议是做成与 `lark-channel/` 并存的新渠道模块；用户未表态。长连接的限制（仅企业自建应用、3 秒内处理完、同一应用多连接时每条事件只发给其中一个）`lark-cli` 同样受着。
